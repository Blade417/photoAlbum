# 星屿 · 3D 星空相册

一个可直接运行的 React + TypeScript + Vite + Three.js 前端工程。照片和视频按拍摄时间排列在三维星空中：最近的回忆离你最近，越久远的越深入星河。支持旋转视角、靠近与远离、平移、穿越到某一年和重温“那年今日”。无需后端服务，素材放入静态目录即可。

## 本地运行

建议使用 Node.js 22 或更新版本。

```sh
npm install
npm run dev
```

在浏览器打开终端显示的本地地址。开发时增删或替换素材会自动重新生成清单，并刷新页面。

```sh
npm run build    # 类型检查并构建到 dist
npm run preview  # 预览构建结果
npm test         # 验证素材扫描、文字配置与保存规则
npm run test:e2e # 浏览器交互验收（默认使用本机 Chrome）
npm run media:scan # 手动重新生成素材清单
npm run media:optimize # 增量生成轻量预览并更新素材清单
npm run media:import # 把放进 public/media 的新照片和视频按拍摄时间改名
```

## 放入自己的照片与视频

将素材放入 **`public/media/`**，统一使用 `memory-` 加编号作为文件名。建议编号至少补齐三位（`001`、`099`、`100`、`1200`），数量没有上限。按添加顺序编号即可，相册会按拍摄时间重新排列。

```text
public/media/
  memory-001.jpg
  memory-002.png
  memory-003.mp4
  memory-003.poster.jpg    # 可选的视频封面
  memory-004.webp
  memory-006.webm          # 允许缺号
  memory-099.jpg
  memory-100.jpg
  memory-1200.mp4
```

- 图片：`jpg`、`jpeg`、`png`、`webp`、`avif`、`gif`。
- 视频：`mp4`、`webm`、`ogg`。实际播放取决于浏览器能否解码文件中的编码；优先使用 H.264 MP4 或 VP8/VP9 WebM。
- `memory-1.jpg` 这种未补零的名称也可以识别，扩展名大小写不敏感。
- 每个编号只对应一个回忆；缺号不会产生空卡片，也不会用演示素材补齐。
- 编号从 `1` 开始，最多 6 位数字；编号 `0` 不会进入相册，子目录中的素材也不会扫描。
- 同一编号存在多个素材时，优先取规范名称（至少三位、没有多余的前导零，如 `memory-007`、`memory-1200`），再依次按 `mp4`、`webm`、`ogg`、`jpg`、`jpeg`、`png`、`webp`、`avif`、`gif` 选择，终端会提示重复。建议主动删除不需要的同编号文件，避免歧义。

### 自动改名

不想手动改名时，把相机、手机或微信里的原文件直接放进 `public/media/`，然后运行：

```sh
npm run media:import -- --dry-run  # 先预览：列出每个文件将得到的新名字，不改动任何文件
npm run media:import               # 正式改名
```

- 只处理还不是 `memory-编号` 格式的文件，已有素材保持不变；新编号接在当前最大编号之后，按拍摄时间从早到晚分配，没有拍摄时间的按原文件名排在最后。
- 只改名，不复制、不转码，文件内容保持不变，扩展名统一为小写；不会覆盖已存在的文件。仍在复制或被占用的文件会被跳过，稍后再运行即可。
- HEIC、RAW（NEF、DNG 等）、MOV 等暂不支持的格式不会改名，脚本会列出来并提示转成 JPG 或 MP4；它们和其他非照片视频文件建议移出 `public/media/`，否则构建时会被复制到 `dist/`。子文件夹不会被导入。
- 开发服务运行中时，改名后会自动生成预览并刷新页面。
- 微信保存的照片和视频通常没有拍摄时间（文件名里的是保存时间），导入后归入“未标注日期”，可以在文字编辑器里补上日期。
- 视频封面使用同编号的 `memory-003.poster.jpg`，也支持 `jpeg/png/webp/avif`。封面不单独占用编号；未提供封面仍可打开并播放视频。

启动开发服务器或执行构建时，工程会自动扫描素材并写入 `public/media-manifest.json`，不必手写任何清单数据。清单里的资源路径会经过 Vite 的 `BASE_URL` 处理，适合部署在站点根目录或子目录。

当目录没有有效素材时，项目显示内置的 99 条演示回忆（88 个图片条目、11 个视频条目，复用 12 张照片和 1 段视频；演示素材没有拍摄日期，按编号排列）。放入第一份有效素材后，演示相册会整体切换为你的素材。演示资源已经存放在本地，正常运行不需要下载；来源见 [public/demo/SOURCES.md](public/demo/SOURCES.md)。

## 拍摄时间与时间星河

生成预览时会在本机读取每份素材的拍摄时间和代表色，写入素材清单：

- 照片：读取 EXIF 的原始拍摄时间（`DateTimeOriginal`，其次 `DateTimeDigitized`），有时区信息时一并保留。不使用修图软件会改写的 `DateTime`。
- 视频：优先读取苹果设备记录的本地时间，其次是容器的 `creation_time`。
- 代表色取自生成的缩略图，用于星云和远处星点的颜色。
- 清单只写入日期时间和颜色，不写入 GPS 或设备信息；预览图仍然不含 EXIF。读取结果按文件指纹缓存，不会重新转码已有预览。

微信转发、截图等素材常常没有拍摄时间：它们在星空里会排在编号相邻、有日期的素材旁边，在总览中归入“未标注日期”。可以在文字编辑器里为它们补上日期，也可以用同样的方式修正相机时钟不准的照片。

有日期的相册会变成一条时间星河：

- 最新的 16 段回忆占据前景，其余沿三条旋臂向远处延伸，越久远的回忆越远。每一年的起点有一道淡淡的光环和年份标记，每一年的星云带着这一年照片的平均色调。
- 素材越多，星河越深，密度保持不变。离得太远的照片会淡出为同色的星点，靠近后重新显现。
- 总览按年份分段，最新的在前；详情和抵达卡片会显示日期。

## 大素材与预览

启动开发服务、构建或执行 `npm run media:optimize` 时，会在本机生成 `public/media-previews/`，原文件保持不变。首次处理大批素材需要一些时间；之后复用缓存，只重新处理新增、替换或缺少预览的文件。

| 用途 | 默认资源 |
| --- | --- |
| 列表、底部缩略图 | 最长边 384 像素的 WebP |
| 星空中的照片 | 最长边 768 像素的 WebP，优先加载视野内照片 |
| 打开的照片 | 最长边 2048 像素的 WebP；下载按钮仍指向原图 |
| 星空中的视频 | 最长边 640 像素、24 帧/秒、最多前 12 秒的静音循环 MP4 |
| 打开的视频 | 按需加载完整原视频，保留声音及播放器控制 |

预览自动校正照片方向，不放大较小的素材，也不保留原图的 EXIF/GPS 元数据。动画图片的星空预览使用首帧，详情保留原动画。视频封面会自动生成，手动提供的同编号封面优先使用。

图片处理最多两张并行，视频逐个转码。星空视频仅加载可见且靠近的素材，电脑最多同时播放 4 个视频源，手机最多 2 个；离开视野约 3.5 秒后释放资源，切换时最多短暂保留 2 个暂停的缓存。手机的照片纹理进一步限制到 512 像素。大相册中，星空只加载视野内、没有淡出为星点的照片；已解码的照片超过约 140 张（手机约 70 张）时，优先释放最久没有看到的。预览生成失败会在终端提示并回退到原素材，下次启动或扫描会重试。

图片由 Sharp 处理，视频由随依赖安装的 FFmpeg 处理，不上传素材。若需要使用本机已有 FFmpeg，可通过 `FFMPEG_PATH` 指定可执行文件。浏览器展示保持纯静态，无须运行转码服务。

`public/media/` 中的私人素材、`public/media-previews/`、自动生成的清单、个人文案 `public/album-content.json` 均被 Git 忽略；首次启动会在配置缺失时生成默认文案，已有配置不会被覆盖。请单独备份原素材和个人文案。构建后的 `dist/` 仍包含原素材，供原图下载和完整视频播放使用；预览优化减少浏览时的加载量，不会删除发布目录里的原文件。

## 修改文字并保存

点击页面右上角的**编辑文字**按钮，打开文字编辑器：

1. 在“页面文字”中修改相册名称、首页标题、介绍、按钮文字和页脚寄语。
2. 在“照片与视频”中按编号或标题搜索，选中素材后修改它的标题、说明和拍摄日期。编号与文件名对应，例如 `memory-003.mp4` 对应 `memory-003`。拍摄日期留空时使用素材记录的时间，填写后会决定这段回忆所在的年份和在星空中的远近。
3. 点击底部保存按钮，修改即应用到相册；编辑器内也支持 `Ctrl + S` / `⌘ + S`。关闭时如果有未保存的修改，会先提示。

编辑器顶部会明确显示保存位置：

- **保存到项目文件**：通过本机 `localhost` 或 `127.0.0.1` 地址访问 `npm run dev` 时，点击“保存到项目”会直接写入 `public/album-content.json`。刷新、关闭浏览器或重启开发服务后仍保留。文案保存不会自动刷新整页、打断编辑；如果用外部编辑器修改 JSON，请刷新页面读取。
- **保存到本机浏览器**：已发布的纯静态网站、`npm run preview`，以及局域网设备访问开发服务时，点击“保存到本机”只会存入当前浏览器中该站点的草稿。同一域名下不同部署目录的草稿相互隔离；其他设备或访客看不到，清除站点数据后草稿也会消失。页面不会把这类保存说成写入服务器。

把修改发布给所有访客：在本机开发服务保存到项目后，重新执行 `npm run build` 并上传整个 `dist/`。如果是在静态网站中编辑，先点“导出”下载 `album-content.json`，将它替换进源工程的 `public/` 后再构建发布；也可以回到开发服务用“导入”载入 JSON，检查后再点“保存到项目”。导入只载入编辑区，不会未经保存就覆盖原有文案；导出包含当前编辑区内尚未保存的有效修改。

页面文案统一保存在 JSON 的 `site` 中；素材文案按编号保存在 `memories.personal` 中。`memories.demo` 专门保存演示相册文字，不会在加入真实照片时串到个人素材上。没有自定义的编号会使用素材清单中的默认标题和说明；替换同编号素材时，会沿用该编号的自定义文字和日期。相册名称不能为空，其余文案允许清空。

配置示例（下方仅展示素材文案部分，完整文件还需保留 `version` 和 `site`）：

```json
"memories": {
  "demo": {},
  "personal": {
    "memory-001": { "title": "第一次一起看海", "subtitle": "2026 年夏天 · 北海" },
    "memory-003": { "title": "生日快乐", "subtitle": "把这段笑声留在星空里", "date": "2024-10-02" }
  }
}
```

不需要修改 `media-manifest.json`：它会在扫描素材时重新生成，而独立的 `album-content.json` 会保留你的文字。当前格式为 `version: 2`；旧的 `version: 1` 文件可以直接读取，下次保存时自动升级。配置会校验结构、编号（`memory-001`、`memory-1200` 这样的规范名称）、长度和日期；标题最多 80 字、说明最多 240 字，`date` 须为 `YYYY-MM-DD` 格式的有效日期，页面文案长度在编辑框旁显示。项目保存失败或浏览器存储不可用时会明确报错，并保留当前编辑，方便导出备份。

## 浏览方式

- 开场：所有回忆先聚成一颗缓缓旋转的星球（最新的 120 段在球面上，手机 60 段，其余藏在核心）。轻触星球，它会在一道闪光中散开，回忆各自飞回时间星河中的位置，星云、年份光环随之浮现；导航栏在散开后出现。星球状态下点击“开始漫游”会先散开再起飞。同一个浏览器标签页只播放一次，刷新（包括添加素材后的自动刷新）直接进入宇宙；开启“减少动态效果”时直接显示宇宙。
- 点击“开始漫游”：从当前分类中随机选择一张照片或视频，用约 3 秒的弧线镜头靠近它（飞往很久远的回忆时稍长），星光随行程温和变亮，抵达后显示对应回忆的标题、日期与入口。重置后再次漫游会重新随机选择，有多份素材时避免连续抵达同一份。可以打开它，也可以继续自由探索。
- 时间坐标：相册有拍摄日期时，右上角显示当前所在的年份。点击后选择一年，镜头会穿越到这一年最后一段回忆的位置。
- 那年今日：如果往年的今天留下过回忆，首页会出现“那年今日”，点击后飞向其中一段。演示相册不显示。
- 入场期间可以点击“跳过”，也可以直接拖动、滚动或按移动键接管；打开总览或编辑器会停止入场。重置视角后可以再次体验。系统开启“减少动态效果”时直接抵达，不播放镜头飞行动画。
- 靠近回忆后重新开启“自动漫游”：镜头会先平滑拉回较宽的星空视野，再围绕星空中心持续旋转。可随时暂停，也可以拖动或滚动接管；空格键与按钮使用相同的切换方式。
- 鼠标左键拖动：旋转观察角度。
- 鼠标滚轮：靠近或远离。
- 鼠标右键拖动：平移观察位置。
- `W / A / S / D`：向前、向左、向后、向右自由移动；`Q / E`：向下、向上移动。
- `R`：重置视角；`Space`：切换自动漫游；`Esc`：关闭弹窗或退出沉浸模式。
- 星空有远近星点、闪烁星光和发光星芒点缀，随视角产生空间层次。
- 三维画面内可见的视频会自动静音循环播放轻量预览，无需点开；离开画面、切换到总览、打开浮层或后台页面时会暂停并释放闲置资源。电脑最多同时解码 4 个不同的视频源，手机最多 2 个，视野内更近的视频优先；重复使用同一视频的卡片共享播放资源。
- 点击一张照片或视频卡片：打开回忆详情，可用播放器控制播放进度和声音。详情中使用左右方向键或两侧箭头切换回忆。
- 详情中的“在星空中靠近”：回到三维星空并移向当前回忆；下载按钮可保存原始图片或视频。
- “相册总览”：以网格浏览全部回忆，有日期时按年份分段，也可以按照片或视频分类。分类不会改变星空布局：符合分类的回忆保持明亮，其余原地变暗、不可点击。
- 触摸屏：单指旋转，双指缩放和平移。

快捷键在星空视图下使用；操作弹窗、视频控件或按钮时，优先遵循控件自身的键盘行为。原始大图可以直接保留在素材目录，预览会自动生成；完整视频仅在打开详情时加载。

自动播放依赖浏览器策略和视频编码：静音自动播放被浏览器拦截时，首次拖动或点击星空会重试；无法解码的视频保留封面或占位图。详情播放器与星空的静音播放独立。

## 部署

执行 `npm run build` 后，将整个 `dist/` 目录上传到静态网站服务器。`vite.config.ts` 默认 `base: './'`，生成的页面、资源清单和素材均使用相对路径。使用 HTTP/HTTPS 访问；不要通过双击 `dist/index.html` 以 `file://` 打开。

更换部署后的素材时，在源工程里更新 `public/media/` 并重新构建、上传 `dist/`。如果直接在服务器更新文件，需要同步重新生成并上传 `media-manifest.json`；服务器不会自行扫描目录。
